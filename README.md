# OpticScope AI · 光链产业证据研究工作台

> 同花顺产品岗位校招笔试｜产业链、跨市场与公司研究｜2026-11-01 研究基线
>
> **产品不是实时证券终端，不输出投资建议。** 项目演示数据来自可点击验证的公开披露；未接入真实扶摇/iFinD MCP认证，绝不冒充实时行情或AI自动核实。

## 1. 产品目标与用户

**目标用户**：研究AI算力产业的个人投资者、股票研究新手、券商研究助理。典型用户不知道“概念股”和“产生对应收入”有什么区别，遇到中美公司横向对标、海外政策或云计算资本开支变化时，也难以判断哪些数据真的可比。

**要完成的任务**：从“热点产业”走到“产业链分层 → 真实业务证据 → 概念评级 → 中美可比与不可比 → 外部事件到财务科目 → 原始材料复核”。不是罗列概念股，也不做股票收益预测。

**行业聚焦**：AI高速光互联（高速光模块800G/1.6T与CPO相关上下游）。先做一个产业的深度样本，再验证其他产业能否复用同一证据模式。

## 2. 启动及运行

### 无需安装依赖（推荐）

```bash
node --version    # Node.js 20+
npm start         # http://localhost:4173
```

也可在项目目录运行 `python -m http.server 4173` 访问静态版（默认本地证据检索）。

另有 **`../OpticScope_AI_交互演示.html`**：嵌入了CSS、JS与研究快照，无需启动服务器，直接浏览器打开即可操作六个工作区。

### 可选：连接真实语言模型

```bash
export OPENAI_API_KEY="你的服务端密钥"
export OPENAI_MODEL="gpt-4.1-mini"
npm start
```

`OPENAI_BASE_URL` 可配置 OpenAI 兼容接口。密钥仅放服务端环境变量，**不要写进前端或 GitHub**。没有密钥时，助手清晰退化为“本地证据检索”，不假装联网LLM。

### 验证

```bash
npm test
npm run check
python scripts/browser_smoke.py
```

`browser_smoke.py` 会使用仓库外的独立单文件版本（在提交包内亦保留 `demo_standalone.html`）进行无网络的真实浏览器按钮测试，覆盖筛选、弹窗、AI回退、数据新增和导出。需要 Python Playwright 和 Chromium。

## 3. 产品结构与关键设计

| 功能 | 可运行交互 | 解决什么问题 |
|---|---|---|
| 产业链总览 | 点击四层链条筛选公司；点击公司查看资料 | 解决“公司到底处于哪一层”的定位问题 |
| 概念可信度 | A–E等级筛选；原始来源跳转 | 区分收入、实际交付、研发计划、传闻、无证据 |
| 中外可比 | 切换4组中美公司组合 | 解释“为何可比”和产品/财年/币种/分部不可比 |
| 事件传导实验室 | 选择3类外部冲击，切换研究强度 | 追溯从外部事件到产品、公司、收入/毛利/库存的条件传导 |
| AI研究助手 | 提问、证据检索、来源编号；服务端LLM可选 | 强制引用、拒绝无出处数字、解释资料边界 |
| 证据库与更新 | 贴入URL/材料 → 规则预审 → 待核验 → JSON导出/导入 | 可持续追加资料而不覆盖原始已核验基线 |

### 产业链分类口径

按照**物理交付功能**拆分四层：(1)芯片、激光器与DSP (2)光器件、光组件与光引擎 (3)高速光模块和互联解决方案 (4)云厂商、AI算力和交换网络需求端。

主层按照报告期内披露的主营收入或最主要产品角色确定；跨环节经营可多层归属，但**不将同一笔公司收入复制给多个环节**。定义于 `data/seed.json > classification.levels`。

### 证据等级与阈值

- **A 已披露收入**：上市公司定期报告披露具体产品/业务分项收入，或者明示“可归属的分部收入”；须保留产品范围、时间、单位、分母。A不代表全为AI收入。
- **B 产品/交付证据**：有明确产品、批量交付或客户应用，但尚无具体概念收入分项。
- **C 研发/规划**：研发、技术路线、经营计划、拟布局等意向披露，不能当销量或已确认收入。
- **D 仅第三方表态**：缺乏可靠一手来源的传闻或描述。
- **E 无足够证据**：不能证实特定主张，**不等于证明公司无业务**。

等级面向**（公司 × 业务概念 × 统计期）具体主张**；不能给公司贴一个永久的总评级。同一家公司的不同主张可以是A和C。新增材料由 `gradeEvidence` 做保守的规则**预审建议**，无论预审得分多少，都永久保留“用户提交 / 待人工复核”状态（直到未来增加审计权限流程；此版本未开放人工核准按钮）。

### 可比性设计

评分维度采用人工定性模板：产品重叠40分、需求驱动25分、业务模式20分、披露可比性15分；对应权重的具体子评分为演示研究判断，**不是行业通用定量模型**。例如中际旭创2025年度光通信收发模块收入对照Coherent FY2026 Datacenter & Communications分部收入，只能作业务/需求对照，**不能直接作纯AI模块收入、毛利率或市占率比较**。

### 外部变化传导

事件被表示为 `trigger → stage → company/business → finance` 的路径集合，每条边附条件。示例“海外AI资本开支上修”仅为情景假设：云厂商资本开支 → 网络端口 → 光模块/器件需求 → 公司产品出货、ASP、毛利率、存货。行业机构预测与公司订单并非一回事；未建立错误的线性增长、股价回归或自动目标价。

## 4. 数据来源、使用与更新时间

- **2025年度中国公司定期报告**：中际旭创、新易盛、天孚通信。
- **FY2026美国公司Form 10-K**：Coherent、Lumentum。不同公司截止日不同，页面显式展示。
- **2026半年度/行业材料**：中际旭创半年报摘要、LightCounting的行业预测（注明“预测非事实”）。
- 来源标识 `S01–S10`，在 `data/seed.json > sources` 中提供 **URL、资料日期、报告期、段落或页码定位、摘要、核验标识**。阅读原文时应结合上下文再确认。
- **数值纪律**：中际旭创FY2025光通信收发模块374.565亿元；新易盛FY2025光互联247.712亿元；天孚FY2025两类器件50.823亿元；Coherent FY2026 DC&C分部52.75亿美元；Lumentum FY2026 Components产品类20.056亿美元。口径异质，不做直接横排增长结论。
- 新证据本地保存在浏览器 `localStorage`，可导出/导入版本化JSON。清除浏览器数据后未导出的内容会丢失；没有账号或服务器共享。
- 后续对接：扶摇提供行情、财务、板块成分；iFinD MCP提供产业链、公告、公司业务、商品、宏观；适配器应先转换成 `{issuer, market, period, metric, value, currency, unit, scope, source_url, published_at}`，再进入人审，不应直接把原始模型回答写成已验证来源。**本版本没有可用认证与接口合同，故未实际调用。**

## 5. AI 角色与安全边界

1. **候选材料预审**：离线规则从文段抽取交付/研发/收入信号，提出A–E候选等级；这不是LLM，也不是事实认证。
2. **RAG式证据问答**：无密钥时由前端基于题库/证据库返回可引用事实，明确“本地证据检索”；服务端设置密钥后由LLM在限定资料范围内生成结构化JSON并仅允许S01-S10来源编号。
3. **证据优先**：商业化表述不能自动升级为营收；“未单列AI收入”不是“没有AI业务”；拒绝无依据的时点预测和交易建议。
4. **限制**：LLM回答虽限制可引用来源ID，**未做严格逐句数值NLI验真**；需要人工审阅原文。不要向问答提交个人/非公开敏感信息。

模型发出的任何编号只能指向现有官方种子库；**若用户新添证据，离线助手可能检索它但需在界面标注待复核**，服务端LLM仅收到原始已核验快照，以免未经验证的数据污染正式结论。

## 6. 已知边界、未做事项

- 不是实时行情/交易系统；未接入扶摇、iFinD MCP真实凭据，也**没有自动定时刷新**，当前是人工/JSON持续更新样本。
- 光模块800G/1.6T、CPO、AI专属销售额大多不是公司普遍披露的同一细分口径；不填补不存在的拆分。
- A股年报和美股10-K币种、财年、业务分类不一致；不跨口径计算可比PE、利润增速和市场份额。
- 定性可比评分与情景路径是产品侧假设，需要未来通过专家访谈与实际数据反馈校正。
- 没做OAuth多用户、协同审核、价格提醒、iFinD授权、行情订阅、预测模型、全市场股票识别、自动PDF抽取、后台任务、合规审核流程。
- 静态站点发布不会包含服务端LLM接口；若需要真实LLM，请部署 Node 服务并在云端配置密钥。

## 7. 部署与提交

仓库内容已按Git仓库格式整理，包括README、测试、数据及脚本。当前环境**无法替使用者登录GitHub/Vercel并发布到公网**，所以不伪造URL。

发布静态版到GitHub Pages：

1. 新建GitHub仓库，上传此目录内容；运行 `git init; git add .; git commit -m 'OpticScope AI v1'`，推送到 `main`。
2. `Settings → Pages → Deploy from a branch → main / (root)`，获得实际 `https://<用户名>.github.io/<仓库名>/` 地址；自行打开确认六个工作区可用。
3. 在提交平台填写**已经打开验证过**的线上Web URL、真实Git仓库URL，不填写本文中的占位示例。
4. 如在Vercel发布静态站，可将项目配置为无构建静态项目；Node端LLM需额外实现Vercel函数适配（当前尚未实现）。

演示视频位于 `demo/OpticScope_AI_功能演示.mp4`；脚本见 `DEMO_SCRIPT.md`，真实性/AI记录见 `AI_VALIDATION.md`，测试结果与缺陷见 `TESTS.md`。
